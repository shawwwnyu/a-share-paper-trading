## 交付能力

- 完整扫描报告现在同时保存 `screening-snapshot-v1` 格式、`availableAt` 和 SHA-256 校验值，内容仍含原目录、原始行情、筛选报告和可选证据。校验覆盖股票池、来源、时间、排除理由和证据；内容变化、报告与原始资料不一致、目录或行情不完整会拒绝作为有效快照。不完整扫描仍保存原始失败记录，不伪装成可验证快照。
- 新的 `dynamic-watchlist-daily-v1` 比较模型，在同一历史目录、行情、交易日历、初始现金、均线策略、费用、滑点与风控下，比较基础观察规则 `liquidity-momentum-v1` 和加入证据的 `liquidity-momentum-evidence-v2`。仅改变筛选规则，便于归因，不以今日自选或配置里的固定股票列表回填过去。
- 决策使用前一次收盘且当时已可知的股票池、证据与此前已结束日线。当前收盘快照只供以后使用，当前日线的价格、成交量不用于当日入场方向或数量上限。截止日前仅预热历史，从截止日后才建立两个独立的模拟组合。
- 候选在决策时和后续成交前均复查当时的证据，包括公开时间、核对时间、有效期、交易状态、公告和公司行为；缺失或未来证据不产生新增买入。行业上限使用方案中冻结的分类，候选证据与分类不一致则阻止买入。
- 每天提供一组真实历史决策盘口及一组确认后的历史成交盘口。两组中的股票统一采用声明的取数时间，后组须晚于前组至少 1 毫秒；模拟确认记在前组之后 1 毫秒。确认仅作为回测假设，不向本人发送交易卡片，也不改变实际交易决定。每天只撮合一次，未成交原因逐笔保留，不将委托滚入下一天。
- 成交复用 `makeFill`、`checkBuyRisk`、`bookFill`、申报数量和退出判断。保留 T+1、现金、费用、最低佣金、盘口深度、涨跌停、滑点和委托有效期；先卖后买，后一笔读取前一笔模拟成交后的组合状态，超限不自动缩量。风险退出优先于均线退出，退出仍只在实际可成交条件满足时执行。触及价格涨跌停或含滑点成交价触及时跳过；数量最多为上一交易日总成交量的 1%。
- 有效日执行已核实的公司行为，只调整此前持仓的股数与现金，历史均线在当时按生效行为调整，不把未来除权信息提前使用。候选开盘证据中的已生效行为须与模拟账本中已登记行为相符。
- 历史成员即使后来移出目录，仍须保留后续日线及盘口，继续估值和评估退出。数据缺失直接判定整份资料无效，不删除亏损股、不丢弃持仓，也不将消失股票当作零市值或免费卖出。新成员均线历史不足时保持等待，不从未来补回过往样本。
- 验证需要已核实交易日历、逐日历史目录、停牌、涨跌停及公司行为资料，日期真实、顺序唯一、每日数据与日历一一对应，并仅使用验证日之前已经结束的交易日。软件只能检查内部一致性，核实标记由导入者负责，校验值不证明外部来源真实或完整。

## 判定与使用

验证输出同时包含模型版本、方案及资料校验值、实际独立区间、逐日股票池引用、模拟成交、未成交原因、期末持仓、含费盈亏、收益率、按每日收盘采样的最大回撤、卖出归因数及费用。期末保留实际模拟持仓并按不复权收盘价估值，不强制清仓，不改写历史账户成绩。

- `valid` 表示数据、时间与覆盖检查及预热/独立区间要求通过，不表示筛选有效。
- 独立区间须晚于 `trainingEnd`、至少 60 个交易日，之前至少有均线窗口所需的预热日数。`trainingEnd` 必须覆盖设定均线参数、筛选阈值及选择方案时已经看过的全部资料，不可为了凑样本提前截止日。
- `passed` 还要求两组各至少 20 笔卖出归因、候选含费收益严格提高且最大回撤未增大；样本不足或条件未通过时保持现有策略。
- `canActivate` 始终为 `false`。这是只读的离线反事实比较，不接入现有候选审批通道，不将固定股池验证结果冒充动态筛选验证，更不能据此直接启用交易策略。本人批准要求保留。

```bash
node src/cli.ts validate-dynamic /私人目录/模拟验证方案.json /私人目录/动态历史资料.json > /私人目录/动态比较结果.json
```

该命令不读取账户数据库。即使方案文件包含数据库路径，也不会打开或创建它；不拉取网络行情、不发送通知。资料无效时仍输出原因并退出码 1；资料有效但效果或样本门槛未通过时退出码 0，须读取 `passed` 与 `reasons`。

方案结构：

```json
{
  "trainingEnd": "调参资料截止日期",
  "strategy": { "id": "simulation-v1", "lookback": 20, "entryBps": 100, "exitBps": 100, "allocationBps": 2000 },
  "account": {
    "cash": 10000000, "commissionBps": 3, "minimumCommission": 500,
    "sellTaxBps": 5, "transferBps": 0.1, "slippageBps": 10,
    "maxQuoteAgeSeconds": 60, "symbols": ["sh600000", "sz000001"]
  }
}
```

日期和股票仅作结构说明，不是推荐参数或本人账户配置。`account.risk` 支持既有风险字段，两个组合始终使用相同冻结配置；`symbols` 不覆盖历史目录。

历史资料根对象：

```text
{
  source: 已独立核实的历史来源与导出说明,
  adjustment: "none",
  marketRulesVerified: true,
  corporateActionsVerified: true,
  universeHistoryVerified: true,
  calendar: { source: 核实的交易日历来源, verified: true, days: 按顺序的全部交易日 },
  sessions: [
    {
      day: 当日日期,
      snapshot: 当日收盘后的完整、带校验值的扫描文件,
      decisionAt: 当日连续竞价中的决策取数时间,
      executionAt: 晚于模拟确认的成交取数时间,
      decisionQuotes: 第一组原始盘口,
      executionQuotes: 第二组原始盘口,
      openingEvidence: 决策时已知的证据文件对象,
      bars: 当日不复权日线（含当日限制、整日停牌标志及已核实公司行为）
    }
  ]
}
```

盘口使用现有 `Quote` 结构，日线使用现有 `Bar` 结构；价格和红利为人民币分、数量为股，证据格式见[第二阶段记录](screening-evidence-result.md)。`openingEvidence` 名称表示本次当日决策时的证据，两次盘口可以选择连续竞价中约定的时点，须在当天收盘快照前。盘中临时停复牌须体现当时盘口及证据，日线 `suspended` 只表示整日停牌。两次盘口及日线必须覆盖截至当日已出现的全部历史目录成员，额外历史日线可以提供均线预热，但不能代替历史目录来源。

本阶段每日一次决策的模型不能代表每五分钟执行、真实确认延迟、盘中价格路径或逐笔撮合。退市清算、现金替代等复杂事件当前不自动模拟；无法提供后续历史价格或合法盘口时，报告资料不足，不能凭空结清。报告的收益率按无出入金的独立组合计算，未接入真实账户份额净值或重算任何实际账本。

## 软件验证与真实验收

先写七组行为测试并运行接口桩，七组均失败，再实现。继续增加历史成员退出后的监控、公司行为和零滑点触及涨跌停/订单到期测试；触及涨跌停边界先复现失败再修复。新增共 10 项测试，原扫描命令测试同时核对已保存快照的格式和校验值。

所有数据均为合成资料，比较直接使用独立内存组合，命令测试仅创建临时输入文件，不打开账户数据库，不连接网络或发送真实通知。在 Node 24.22.3 下通过 `npm test`（92/92，原有 82 项与新增 10 项）、`npm run typecheck`、`npm run format:check`。本阶段未修改中台接入模块，验证过程未启动中台服务或发送消息。

尚无已独立核实并覆盖截止日后 60 个交易日的真实动态资料，本轮不宣称筛选效果验证通过。需从真实可知时间持续积累完整收盘快照、当时证据、两个决策/成交时点的盘口及公司行为资料，再独立核实来源后运行比较。既有账户未启用新阈值或新策略。
