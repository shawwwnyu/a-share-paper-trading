## 时点、账本与历史事实

- `Ledger.view(to)` 用同一条 SQLite 查询按顺序恢复截止时点已登记的变动及操作记录。同一时间连续登记但没有重复保存 `lastAt` 的记录，继承前一条时间。晚于截止时点的记录不进入视图，不重新执行交易、行情、费用或策略计算，也不修改原表格式和旧记录。
- 日报、周报的统计视图须不晚于报告截止时点，不能把当前已经成交或已拒绝的状态带回先前仍待确认的报告。日报取北京时间自然日，从前一日最后 1 毫秒之后计数，截止到该日结束或指定的当前时点，以较早者为准；当天尚未结束会明确说明。
- 金额、资金进出、份额净值、费用和 FIFO 盈亏继续采用原账本数值与复盘口径。不构造昨天的估值，不以新策略重算旧成绩。日报在收盘后缺少当日收盘估值时，资金收益指标标为资料不足；缺少期初、长期估值缺口等原检查仍保留。
- 日报读取及写报告文件本身不追加账本操作、不生成交易或策略审批，也不会创建未初始化账户。运行中的交易检查、扫描和收盘估值则增加明确的检查记录或风险快照，作为以后复盘的事实来源；这些记录不改变现金、持仓、成交或策略。

## 分开统计的工作流

| 分项 | 统计口径 |
| --- | --- |
| 筛选 | 本期账本完整扫描和已记录的不完整扫描数量、每次目录与行情覆盖、规则及报告引用、累计入选和排除原因、自选进入与退出。累计入选允许同股跨次重复，不是独立股票数。 |
| 信号 | 按登记时间统计成功生成的信号，按策略与买卖方向分组；被行情、证据、预算或其他检查阻止生成的尝试单列，不虚构成功信号。没有方向的风险检查错误单列为数据检查失败。 |
| 确认 | 使用本人实际决定时间减信号时间，包含批准、拒绝、已确认未成交和确认时已过期的决定；列出数量、平均、中位数和 95 分位延迟。原周报仅成交样本的平均延迟字段也保留，二者分母不同。批准指记录本人同意，不等于具备成交资格。 |
| 执行与未成交 | 成交数和费用按实际成交事实统计；已记录的未成交检查同时列尝试次数与涉及委托数，按原因分组。待确认、已确认待成交、本期已登记过期或拒绝分别保留。已到期或策略已变但还没登记清理的委托单列，不为报表擅自改写状态。 |
| 交易归因 | 已实现交易盈亏按记录中的入场策略、退出策略分别分组，不按当前启用版本重算。两组是同一份 FIFO 盈亏的不同观察方式，不能相加；保留原周报入场归因字段。成交费用及相对信号价执行差额按成交时策略单列。 |
| 风险 | 保存日常交易检查后与收盘估值后的实际持仓风险快照，含现金、持仓市值、总仓位、单股和行业仓位、持仓数、T+1 可卖数量、止损止盈和持有期限提示。已移出自选但仍持有的股票照常计入。 |

检查记录按稳定操作编号幂等写入，同一时点、同一内容的重派不重复记数；不同轮次的检查仍保留各自事实。扫描不完整时只登记观察，保留原自选，不能批准交易。生成完整报告前即中断的取数轮次不会凭空计入成功或不完整扫描。

风险估值需要每只实际持仓的本次当日有效行情，不能以缓存旧价填补缺失；缺价时资产和仓位比例标为未知，不把缺失股票算成零市值。不相关的无持仓股票旧行情不影响组合覆盖。行情重复、过期、未来或冻结行业分类缺失会明确显示资料不足。行业分类和风险阈值仍取自初始化后冻结的账户配置，不自动启用新设置。

最近一次已记录风险快照保留当时计算结果和时间；报告截止时点的风险另作只读诊断，二者不冒充同一个时点。日报隔天查看时，旧行情可能不再满足当前风险估值时效，此时保留最近快照并显示当前资料不足。风险提示不是强制平仓，不自动确认退出，也不跳过 T+1、费用、盘口或涨跌停检查。

旧轮次没有保存的检查不能回填成“成功”“没有风险”或具体未成交原因。报告明确说明统计覆盖边界；本次没有使用新逻辑补造历史流水。

## 日常使用与文件

```bash
node src/cli.ts daily-review account.json 2026-11-13
```

命令输出中文日报，并写入账户报告目录的 `daily/YYYY-MM-DD.json` 与 `.md`；它们指向最近截止时点的报告内容。完整内容同时按日期及校验值保存在 `daily/versions/`，已经保存的版本不覆盖。重看较早截止时点会恢复相同旧版本，不替换较新日报。

原 `agent-mark` 成功收盘估值后，会从账本生成当日日报，不增加新定时规则或通知。若估值已登记但报告文件未保存，重派只从账本恢复报告，不重新抓行情或重复估值。已有“估值只登记一次”的回归断言保留；相关测试的报告路径移到临时目录，避免测试写入工作区私人目录。

Loop 新增“查看日报”或“查看每日复盘”，读取最近日报；“查看复盘”“查看周报”继续读取周报。周报增加同样的工作流统计与策略归因，保持既有财务字段和审批协议。已有足够卖出样本时也默认保持现有策略，不因为进入新的复盘周期就要求调参；发现明确问题时，原单项待验证假设流程仍保留，启用依然需要独立验证和本人批准。日报本身不登记候选策略。

没有部署到运行副本前，线上收盘流程和 Loop 不会取得本次新功能。本轮只提交开发分支，运行副本待独立复核更新；不修改中台仓库、运行规则、账户参数、真实账户或凭据。
